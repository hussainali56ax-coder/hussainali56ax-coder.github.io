🖥️ دليل تثبيت لوحة 3x-ui (V2Ray/Xray) على VPS

هذا الدليل يشرح كيفية تثبيت لوحة التحكم 3x-ui على سيرفر VPS يعمل بنظام Ubuntu أو Debian، وتأمينها بشكل صحيح.

⚠️ تحذير أمني مهم — اقرأه قبل البدء!
  • 🚫 لا تشارك أي أحد عنوان IP الخاص بسيرفرك، أو اسم المستخدم (root)، أو كلمة مرور SSH.
  • 🚫 لا تُرسل بيانات اعتماد لوحة التحكم (المستخدم/كلمة المرور) عبر أي قناة تواصل (تيليغرام، واتساب، إلخ).
  • ✅ إذا احتجت مساعدة في تشخيص مشكلة، شارك النصوص التي تظهر في الطرفية فقط (رسائل الخطأ) بعد إخفاء أي IP أو بيانات حساسة.
  • ✅ نفّذ الأوامر بنفسك من داخل SSH، ولا تدع أي شخص يتصل بسيرفرك عن بُعد بدون إشرافك الكامل.
  • ✅ غيّر كلمة مرور SSH الافتراضية فوراً بعد استلام السيرفر، وفعّل المصادقة بالمفتاح (SSH Key) إن أمكن.

1. المتطلبات الأساسية

قبل البدء، تأكد من توفر ما يلي:

  • ✅ سيرفر VPS يعمل بنظام Ubuntu 20.04 / 22.04 أو Debian 10 / 11 / 12
  • ✅ وصول Root عبر SSH (عنوان IP + كلمة مرور، أو مفتاح SSH)
  • ✅ اتصال إنترنت مستقر على السيرفر
  • ✅ برنامج SSH على جهازك (انظر أدناه)

برامج SSH الموصى بها:

  • 🪟 Windows: PuTTY أو Windows Terminal (مدمج في ويندوز 11)
  • 🍎 macOS / Linux: التطبيق المدمج Terminal
  • 📱 Android: JuiceSSH أو Termius

2. الاتصال بالسيرفر عبر SSH

  1. افتح Terminal أو PuTTY على جهازك.
  2. اكتب الأمر التالي واستبدل YOUR_IP بعنوان IP السيرفر الخاص بك: 
    ssh root@YOUR_IP
  3. عند طلب كلمة المرور، أدخلها (لن تظهر أي أحرف أثناء الكتابة — هذا طبيعي).
  4. بعد الدخول الناجح، ستظهر لك واجهة الطرفية وسترى شيئاً مثل: 
    root@vps:~#
💡 نصيحة: إذا كانت المرة الأولى وظهرت رسالة "Are you sure you want to continue connecting?" اكتب yes واضغط Enter.

3. تثبيت 3x-ui

بعد الدخول للسيرفر، نفّذ الأوامر التالية بالترتيب:

الخطوة 1 — تحديث النظام أولاً (ضروري)

apt update && apt upgrade -y

الخطوة 2 — تثبيت 3x-ui بأمر واحد

bash <(curl -Ls https://raw.githubusercontent.com/mhsanaei/3x-ui/master/install.sh)
💡 ماذا يحدث؟ هذا الأمر يحمّل سكربت التثبيت الرسمي من GitHub ويشغّله. السكربت سيسألك خلال التثبيت عن:
  • اسم مستخدم لوحة التحكم
  • كلمة مرور لوحة التحكم
  • رقم البورت (Port) للوحة التحكم

اختيار اسم مستخدم وكلمة مرور قويين

  • اختر اسم مستخدم غير متوقع (ليس admin أو root)
  • كلمة المرور: استخدم مزيجاً من الأحرف الكبيرة والصغيرة والأرقام والرموز (مثل: Kx9!vP2@mQ)
  • اختر بورتاً مختلفاً عن الافتراضي 2053 (مثلاً 8443 أو أي رقم بين 1024–65535)

الخطوة 3 — التحقق من أن الخدمة تعمل

systemctl status x-ui

إذا كانت الخدمة تعمل بشكل صحيح، ستظهر كلمة active (running) باللون الأخضر.

4. الدخول للوحة وأول إعداد

  1. افتح المتصفح على جهازك وانتقل إلى: 
    http://YOUR_IP:YOUR_PORT
    مثال: http://1.2.3.4:8443
  2. أدخل اسم المستخدم وكلمة المرور اللذين اخترتهما أثناء التثبيت.
  3. بعد الدخول:
    • اذهب إلى قائمة Inbounds
    • اضغط على Add Inbound
    • اختر البروتوكول المناسب (مثل VLESS أو VMess)
    • حدد رقم البورت، ثم احفظ
    • انسخ رابط الاتصال (أو كود QR) وأضفه في تطبيق V2Ray على جهازك
💡 تطبيقات V2Ray الموصى بها:
🖥️ Windows: V2rayN | 🤖 Android: V2rayNG أو NapsterNetV | 🍎 iOS: Streisand أو Shadowrocket

5. تأمين لوحة التحكم

5.1 تغيير بورت لوحة التحكم

من داخل الطرفية، يمكنك تغيير البورت في أي وقت عبر قائمة إدارة 3x-ui:

x-ui

ستظهر قائمة رقمية. اختر الخيار المناسب لتغيير الإعدادات (عادةً خيار Settings).

5.2 تغيير اسم المستخدم وكلمة المرور

يمكنك تغيير بيانات الدخول من نفس قائمة x-ui أو من داخل لوحة التحكم ← Settings.

استخدم دائماً كلمة مرور من 12 حرفاً على الأقل تحتوي على أرقام ورموز وأحرف مختلطة.

5.3 ضبط جدار الحماية (UFW) لإغلاق البورتات غير الضرورية

# تفعيل UFW
ufw enable

# السماح بـ SSH (مهم جداً — لا تتجاهل هذه الخطوة!)
ufw allow 22/tcp

# السماح ببورت لوحة 3x-ui (استبدل 8443 ببورتك)
ufw allow 8443/tcp

# السماح ببورتات الاتصال الخاصة بـ inbounds (استبدل بالبورت الذي أنشأته)
ufw allow 443/tcp
ufw allow 80/tcp

# عرض الحالة
ufw status
⚠️ تحذير: لا تفعّل UFW قبل السماح لـ SSH (البورت 22)!
  • إذا فعّلت UFW دون السماح لبورت 22، ستُقفل خارج السيرفر تماماً.
  • تأكد دائماً من تنفيذ ufw allow 22/tcp قبل ufw enable.

5.4 تغيير بورت SSH الافتراضي (اختياري — لكن موصى به)

تغيير بورت SSH من 22 إلى رقم آخر يقلل محاولات الاختراق التلقائية:

# افتح ملف إعدادات SSH
nano /etc/ssh/sshd_config

# ابحث عن السطر: #Port 22
# غيّره إلى (مثلاً): Port 2222

# ثم أعد تشغيل SSH
systemctl restart ssh

# لا تنسَ السماح للبورت الجديد في UFW
ufw allow 2222/tcp

6. استكشاف الأخطاء وإصلاحها

6.1 التحقق من حالة خدمة 3x-ui

systemctl status x-ui

إذا كانت الخدمة متوقفة (inactive أو failed)، شغّلها مجدداً:

systemctl restart x-ui

لجعل الخدمة تبدأ تلقائياً عند إعادة تشغيل السيرفر:

systemctl enable x-ui

6.2 عرض سجلات الأخطاء (Logs)

# آخر 50 سطر من سجل x-ui
journalctl -u x-ui -n 50

# متابعة السجل بشكل مباشر (اضغط Ctrl+C للخروج)
journalctl -u x-ui -f
💡 عند طلب المساعدة: يمكنك نسخ ما يظهر من journalctl (بعد إخفاء IP السيرفر) ومشاركته للحصول على دعم، دون الحاجة لمشاركة كلمة المرور أو IP.

6.3 التحقق من البورتات المفتوحة

# عرض البورتات التي تستمع عليها الخدمات
ss -tlnp

# أو باستخدام netstat
netstat -tlnp

6.4 التحقق من حالة UFW وفتح بورت معين

# عرض قواعد جدار الحماية
ufw status verbose

# فتح بورت محدد (استبدل PORT برقم البورت)
ufw allow PORT/tcp

# إعادة تحميل القواعد
ufw reload

6.5 فحص الاتصال من السيرفر نفسه

# هل اللوحة تستجيب على البورت المحدد؟ (استبدل 8443 ببورتك)
curl -s -o /dev/null -w "%{http_code}" http://127.0.0.1:8443

إذا كانت الاستجابة 200 أو 302، فاللوحة تعمل. المشكلة قد تكون في جدار الحماية أو مزوّد الخدمة (يلزم فتح البورت من لوحة VPS).

6.6 أخطاء شائعة وحلولها

  • "Connection refused" عند فتح اللوحة: تحقق من أن الخدمة تعمل (systemctl status x-ui) وأن البورت مفتوح في UFW ولوحة التحكم الخاصة بمزوّد الـ VPS.
  • "This site can't be reached": تأكد من صحة IP والبورت. تحقق من UFW. تأكد من أن مزوّد الـ VPS لا يحجب البورت.
  • خدمة x-ui تتعطل باستمرار: اقرأ السجل عبر journalctl -u x-ui -n 100 لمعرفة سبب الخطأ.
  • نسيت كلمة مرور اللوحة: من الطرفية نفّذ x-ui واختر خيار Reset Credentials.

7. تفعيل HTTPS (TLS) عبر Nginx أو Caddy — اختياري

تشغيل اللوحة على HTTP فقط يعني أن البيانات تنتقل بدون تشفير. إضافة TLS (HTTPS) يُحسّن الأمان بشكل كبير.

💡 المتطلب: تحتاج إلى اسم نطاق (Domain) مرتبط بـ IP السيرفر لإصدار شهادة SSL مجانية.

الخيار الأول: Caddy (الأسهل)

Caddy يدير شهادة SSL تلقائياً بدون أي إعداد معقد:

# تثبيت Caddy
apt install -y debian-keyring debian-archive-keyring apt-transport-https
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/gpg.key' | gpg --dearmor -o /usr/share/keyrings/caddy-stable-archive-keyring.gpg
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/debian.deb.txt' | tee /etc/apt/sources.list.d/caddy-stable.list
apt update && apt install caddy -y

ثم أنشئ ملف إعداد Caddy (/etc/caddy/Caddyfile):

your-domain.com {
    reverse_proxy 127.0.0.1:8443
}

أعد تشغيل Caddy:

systemctl restart caddy

الآن يمكنك الدخول عبر: https://your-domain.com

الخيار الثاني: Nginx + Certbot

# تثبيت Nginx و Certbot
apt install -y nginx certbot python3-certbot-nginx

# إنشاء ملف إعداد Nginx (استبدل your-domain.com بنطاقك)
cat > /etc/nginx/sites-available/3x-ui <<'EOF'
server {
    listen 80;
    server_name your-domain.com;

    location / {
        proxy_pass http://127.0.0.1:8443;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
    }
}
EOF

ln -s /etc/nginx/sites-available/3x-ui /etc/nginx/sites-enabled/
nginx -t && systemctl reload nginx

# إصدار شهادة SSL مجانية من Let's Encrypt
certbot --nginx -d your-domain.com

بعد نجاح العملية، ستتحول اللوحة إلى HTTPS تلقائياً.

✅ تهانينا! الآن لوحتك تعمل على HTTPS وهي أكثر أماناً. تذكر تجديد الشهادة تلقائياً عبر: 
certbot renew --dry-run

# قائمة إدارة x-ui التفاعلية
x-ui
